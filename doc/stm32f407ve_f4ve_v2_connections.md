# Подключение модулей к STM32F407VE (STM32_F4VE_V2.0)

Документ относится к плате `STM32F407VET6 STM32_F4VE_V2.0` и проекту
`sdk/gstr-bios`. Основная конфигурация проекта находится в
`sdk/gstr-bios/gstr-bios.ioc`.

Все GPIO микроконтроллера работают с логическими уровнями 3,3 В. Земли платы
и всех внешних модулей должны быть соединены.

> Названия `PA2`, `PA5`, `PE11` и подобные ниже соответствуют маркировке GPIO
> на выводных разъёмах платы. Номер физического контакта разъёма зависит от
> исполнения платы, поэтому при подключении нужно ориентироваться на
> обозначение GPIO на шелкографии, а не на порядковый номер контакта.

## Питание

Плату можно питать штатным способом через её USB-разъём либо через контакт
`5V`, если источник имеет стабилизированные 5 В и правильную полярность.
Нельзя одновременно соединять несколько источников 5 В, если не проверена
схема их развязки.

- Сигнальные входы STM32 нельзя подключать к логике 5 В без проверки
  5V-tolerance конкретного вывода.
- Питание `3V3` платы предназначено для маломощной периферии.
- Для дисплея и WS2812 обязательна общая земля с платой.

## Дисплей ILI9341 по SPI

Дисплей подключён к `SPI1` только на передачу; параллельный TFT/FSMC-разъём платы в этой
конфигурации не используется.

| ILI9341 | STM32_F4VE_V2.0 |
|---|---|
| `SCK`, `CLK` | `PA5` |
| `MOSI`, `SDI`, `SDA` | `PA7` |
| `CS` | `PB0` |
| `RESET`, `RST` | `PB1` |
| `DC`, `RS`, `A0` | `PC6` |
| `GND` | `GND` |
| `MISO`, `SDO` | не подключать |

Линия `MISO` программой не используется. Линии SPI и управления имеют уровень
3,3 В.

Питание дисплейного модуля зависит от его исполнения:

- модуль без стабилизатора и преобразователей уровней подключается к `3V3`;
- модуль с явно указанным входом `5V` может питаться от `5V`, но его логические
  входы всё равно должны принимать уровень 3,3 В;
- если тип модуля неизвестен, сначала нужно проверить его схему или маркировку.

`PB2` не используется дисплеем и остаётся исключительно линией `BOOT1`.
Перемычки режима загрузки должны оставаться в положении загрузки из
пользовательской Flash (`BOOT0 = 0`).

## Два последовательно соединённых WS2812

Подключение модуля:

| Модуль WS2812 | STM32_F4VE_V2.0 |
|---|---|
| `DIN` | `PE11` |
| `5V`, `VCC` | `5V` |
| `GND` | `GND` |
| `DOUT` | не подключать, если следующего модуля нет |

Если используются два отдельных светодиода, а не готовый двухсветодиодный
модуль, соединение должно быть последовательным:

```text
PE11 ──> DIN LED1
          DOUT LED1 ──> DIN LED2
                         DOUT LED2 ──> не подключать

5V  ──> VCC LED1 и VCC LED2
GND ──> GND LED1 и GND LED2 и GND платы
```

Рекомендуется установить резистор 220–470 Ом последовательно между `PE11` и
`DIN` первого светодиода, а рядом с модулем — конденсатор не менее 100 мкФ
между `5V` и `GND`.

WS2812 питается от 5 В, поэтому уровень 3,3 В на `PE11` формально может быть
ниже гарантированного порога входа некоторых партий WS2812. Для надёжного
устройства следует поставить преобразователь уровня с 3,3 до 5 В, например
один канал `74AHCT125` или `74HCT14`. Для короткого провода два светодиода
часто работают непосредственно от `PE11`, но это не гарантируется
спецификацией.

Для управления используются функции:

```c
WS2812_SetLed1Color(red, green, blue);
WS2812_SetLed2Color(red, green, blue);
```

Пример:

```c
WS2812_SetLed1Color(255, 0, 0);  // LED1: красный
WS2812_SetLed2Color(0, 255, 0);  // LED2: зелёный
```

Цвет второго светодиода сохраняется при изменении первого и наоборот.

## Встроенная microSD

Дополнительные провода не нужны: слот microSD уже установлен на плате.
Проект использует его в четырёхбитном режиме SDIO:

| Сигнал SDIO | GPIO |
|---|---|
| `SDIO_D0` | `PC8` |
| `SDIO_D1` | `PC9` |
| `SDIO_D2` | `PC10` |
| `SDIO_D3` | `PC11` |
| `SDIO_CK` | `PC12` |
| `SDIO_CMD` | `PD2` |

Тактовая линия работает в безопасном режиме 24 МГц без clock bypass. Карта
сначала инициализируется на одной линии, затем прошивка отправляет ACMD6 и
переключает карту и контроллер в режим 4-bit. Контакт Card Detect в слоте не
подключён, поэтому программа
считает карту установленной и определяет её наличие при попытке
инициализации.

## Встроенный индикатор

Один из штатных светодиодов платы используется как индикатор состояния на
`PA6`. Он подключён к питанию через резистор, поэтому активен низким уровнем:
`GPIO_PIN_RESET` включает LED, а `GPIO_PIN_SET` выключает.

## Часы реального времени

RTC работает от установленного на плате кварца 32,768 кГц. Выводы кварца
`PC14/OSC32_IN` и `PC15/OSC32_OUT` уже разведены на плате, подключать к ним
внешние устройства не нужно.

Для сохранения времени при отключении основного питания в держатель `BAT`
нужно установить батарейку, соответствующую держателю и схеме платы. Батарейка
питает домен `VBAT`; без неё часы продолжают работать только пока плата
получает основное питание.

Интерфейс часов объявлен в `sdk/middleware/include/rtc/rtc_clock.h`, а
реализация находится в `sdk/middleware/rtc/rtc_clock.c`:

```c
RTC_ClockDateTime current_time;

RTC_Clock_Set(2026, 7, 28, 12, 30, 0);
RTC_Clock_Get(&current_time);
```

При первом запуске устанавливается начальное значение
`2026-01-01 00:00:00`. Последующие сбросы микроконтроллера его не
перезаписывают. После старта прошивка выводит текущую дату и время через UART:

```text
RTC: 2026-01-01 00:00:01
```

## UART для диагностического вывода

Проект выводит сообщения `printf()` через `USART1`, 115200 бод, 8 бит данных,
без чётности, один стоп-бит.

| USB–UART | STM32_F4VE_V2.0 |
|---|---|
| `RX` | `PA9` (`USART1_TX`) |
| `TX` | `PA10` (`USART1_RX`) |
| `GND` | `GND` |

Использовать нужно USB–UART с логическими уровнями 3,3 В. Контакт питания
адаптера подключать не требуется, если плата уже питается отдельно.

Можно использовать штатный четырёхконтактный разъём `ISP_COM`, который
подключён к `USART1` (`PA9/PA10`). Линии соединяются крест-накрест:
`TX` платы с `RX` адаптера, `RX` платы с `TX` адаптера.

## Внешняя клавиатура

Кнопки активны низким уровнем: один контакт каждой кнопки подключается к
указанному GPIO, второй — к `GND`. Входы имеют программную подтяжку вверх.

| Код кнопки | GPIO |
|---|---|
| `KBRD_BTN_UP` | `PE6` |
| `KBRD_BTN_DOWN` | `PB4` |
| `KBRD_BTN_LEFT` | `PE7` |
| `KBRD_BTN_RIGHT` | `PB6` |
| `KBRD_BTN_1` | `PB7` |
| `KBRD_BTN_2` | `PB8` |
| `KBRD_BTN_3` | `PB9` |
| `KBRD_BTN_4` | `PB9` |

В текущем драйвере `KBRD_BTN_3` и `KBRD_BTN_4` ошибочно назначены на один и тот
же `PB9`. Эти две кнопки нельзя различить, пока для `KBRD_BTN_4` не будет
выбран отдельный свободный GPIO и одновременно исправлены код и `.ioc`.
Остальные четыре описанные в `keyboard.h` функции кнопок пока не внесены в
таблицу `key_map`.

## Внешний I2S DAC

Если используется модуль PCM5102 или совместимый DAC:

| I2S DAC | STM32_F4VE_V2.0 |
|---|---|
| `LCK`, `LRCK`, `WS` | `PA4` |
| `BCK`, `BCLK` | `PB3` |
| `DIN`, `DATA` | `PB5` |
| `SCK`, `MCLK` | `GND` |
| `GND` | `GND` |

PCM5102A используется в трёхпроводном режиме: его внутренний PLL восстанавливает
системную тактовую частоту из `BCK`. Выход `I2S3_MCK` в прошивке отключён, а
`PC7` освобождён. Питание DAC следует подключать согласно документации
конкретного модуля.

Выбор выводов у `I2S3` на STM32F407 жёстко ограничен. Линия данных `I2S3_SD`
существует только на `PB5` и `PC12`, причём `PC12` занят `SDIO_CK` встроенной
microSD, поэтому для `DIN` остаётся единственный вариант — `PB5`. Ранее в этом
документе и в проекте была указана `PD6`: у STM32F405/407 этот вывод
поддерживает только `FSMC_NWAIT`, `USART2_RX` и `EVENTOUT`, а `SPI3_MOSI/I2S3_SD`
на `PD6` появился лишь в STM32F42x/F43x. С `PD6` тактовые линии работали, но
данные не выводились, то есть звука не было. Из-за занятой `PB5` кнопка
`KBRD_BTN_LEFT` перенесена на `PE7`.

Для четырёхбитного SDIO линия `PC10` используется как `SDIO_D2`, поэтому `BCK`
перенесён на `PB3`. Вывод трассировки `SWO` отключён; прошивка и отладка по
`SWD` на `PA13/PA14` сохраняются.

### Требования PCM5102A к частоте `BCK`

Встроенный PLL восстанавливает системную частоту DAC из `BCK`, и таблица 11
даташита `PCM510xA` задаёт для этого допустимые значения `BCK`: разрешены
отношения 32, 48 и 64 `fS`, но абсолютная частота не может быть ниже
1,024 МГц. Если соотношение `LRCK` и `BCK` остаётся недопустимым дольше
четырёх периодов `LRCK`, DAC переинициализируется и прижимает выход к
биполярному нулю, а на слух это воспринимается как треск вместо звука.

Поэтому 16-битные отсчёты передаются в 32-битных канальных кадрах
(`I2S_DATAFORMAT_16B_EXTENDED`): кадр занимает 64 `BCK`, и при 22 кГц
получается 1,41 МГц вместо запрещённых 705,6 кГц у 32 `fS`. Оставшиеся
16 бит канала дополняются нулями аппаратно, поэтому на каждый канал
по-прежнему пишется одно полуслово.

### Тактирование звука

При `HSE` 8 МГц и `PLLM = 4` на входе VCO получается рекомендованные ST 2 МГц,
а `PLLI2SN = 146`, `PLLI2SR = 3` дают `PLLI2S` 97,333 МГц. Для 16-битного
стерео в формате Philips с 32-битным каналом и без `MCLK` HAL выбирает
`I2SDIV = 34`, `ODD = 1`, то есть частоту дискретизации 22040,6 Гц при
запрошенных 22050 Гц — отклонение 0,04 %. Прошивка печатает фактические
значения в UART при старте:

```text
I2S: clock=97333333 Hz, sample_rate=22041 Hz, bclk=1410624 Hz, prescaler=69
```

Для смены частоты дискретизации нужно перенастраивать `PLLI2S` вместе с
`HAL_I2S_Init`: например, для 44100 Гц подходят `PLLI2SN = 144`,
`PLLI2SR = 3` (`PLLI2S` 96 МГц, `I2SDIV = 17`, `ODD = 0`, `BCK` 2,82 МГц).

### Потоковая передача

Воспроизведение вынесено в модуль `sdk/middleware/audio/audio.c` с интерфейсом
`sdk/middleware/include/audio/audio.h`. Настройка периферии остаётся за
приложением: `main.c` инициализирует `I2S3` вместе с DMA и передаёт хендл в
`Audio_Init()`, после чего модуль отвечает только за поток отсчётов.

```c
Audio_Init(&hi2s3, BIOS_AudioAbortRequested);  /* второй аргумент может быть NULL */
Audio_GetClockInfo(&info);                     /* фактические частоты */
Audio_PlayTestBeep();                          /* три импульса */
Audio_PlayPcmFile("music.pcm");                /* сырой PCM с карты */
```

Передача в `SPI3` идёт через `DMA1_Stream5`, канал 0 (`DMA_CIRCULAR`,
полуслова), обработчик `DMA1_Stream5_IRQHandler` уже подключён. Кольцевой буфер
рассчитан на 1024 стереокадра в половине, то есть около 46 мс запаса.

Блокирующий `HAL_I2S_Transmit` для звука не подходит: у периферии есть только
один регистр данных, поэтому пока считается следующий блок отсчётов, поток
пересыхает и DAC получает повторы предыдущего отсчёта на каждой границе блоков.

Колбэки `HAL_I2S_TxHalfCpltCallback` и `HAL_I2S_TxCpltCallback` только помечают
освободившуюся половину, а заполняется она из основного контекста. Читать SD
прямо в колбэке нельзя: `HAL_SD_ReadBlocks` ждёт по `HAL_GetTick`, а `SysTick`
имеет приоритет `TICK_INT_PRIORITY` (15) против приоритета 0 у `DMA1_Stream5`,
поэтому внутри прерывания счётчик тиков не растёт и любой таймаут зависает.

## Воспроизведение звука с SD-карты

При старте, сразу после трёх тестовых импульсов, прошивка проигрывает файл
`music.pcm` из корня карты. Формат совпадает с тем, что ждёт периферия, поэтому
данные уходят в `SPI3` без разбора заголовков и преобразований:

| Параметр | Значение |
|---|---|
| частота дискретизации | 22050 Гц |
| каналы | стерео |
| отсчёты | знаковые 16-битные, little-endian |
| порядок | `L0`, `R0`, `L1`, `R1`, … |
| контейнер | отсутствует, только сырой PCM |

Файл готовит `sdk/tools/audio-to-pcm.sh`:

```sh
sdk/tools/audio-to-pcm.sh music.mp3 MUSIC.PCM
```

FatFs собран без поддержки длинных имён (`_USE_LFN = 0`), поэтому имя на карте
должно укладываться в 8.3; регистр значения не имеет. Любой заголовок в файле
будет проигран как шум, так что конвертировать нужно именно в сырой PCM.

Прерывание воспроизведения задаёт приложение: `main.c` передаёт в `Audio_Init()`
обработчик, который опрашивает клавиатуру, поэтому любая кнопка останавливает
поток. Без этого загрузка ждала бы конца файла, а он может длиться минуты. Если
карта не смонтировалась или файла нет, прошивка сообщает об этом в UART и
продолжает загрузку.

Имя файла в прошивке задано макросом `BIOS_MUSIC_FILE` в `main.c`; сам модуль
никакого имени по умолчанию не знает и в UART не пишет — весь вывод остаётся за
приложением.

## Отладка и прошивка

Для SWD используются:

| Отладчик | STM32 |
|---|---|
| `SWDIO` | `PA13` |
| `SWCLK` | `PA14` |
| `NRST` | `RST` / `NRST` |
| `GND` | `GND` |
| `VTref` | `3V3` |

Отладчик не должен подавать 5 В на сигнальные линии. Для нормального запуска
перемычка `BOOT0` должна выбирать пользовательскую Flash.
